# CLAUDE.md

Інструкції для AI-асистентів (Claude Code та подібних), що працюють над цим
репозиторієм.

## Про проєкт

`scan-detector` — набір bash-скриптів навколо `nftables` для детекції
сканування портів і прогресивного graylisting (IPv4/IPv6), із захистом і
хоста (`input`), і docker-контейнерів (`forward`, per-bridge). Деталі логіки —
в [README.md](README.md).

## Мова спілкування

Завжди відповідати **українською мовою**. **Спілкуємося українською.** Це
головна вимога.

- Усі відповіді, пояснення, аналіз і опис процесу виконання — **українською мовою**.
- Повідомлення комітів, коментарі в bash-скриптах — **українською** (виняток:
  усталені англомовні технічні терміни, назви nft-сетів/ланцюгів/змінних,
  назви прапорців командного рядка).
- Текст, що йде в `nft ... log prefix "..."` та інші рядки, які потрапляють у
  системні логи (`journalctl`, `dmesg`) — англійською, як склалося історично в
  проєкті (напр. `scandetect-input-drop`). Не змішувати мови в межах одного
  такого рядка.
- Ідентифікатори в коді (функції, змінні, назви nft-сетів/ланцюгів) —
  англійською, за конвенціями shell (`snake_case` для функцій і змінних,
  `UPPER_CASE` для констант/env).

## Обов'язкове правило при кожному коміті

Якщо змінюється код (скрипти, systemd-юніти, логіка nft-правил) — в тому
самому коміті оновлюються:

- **`CHANGELOG.md`** — новий запис під `[Unreleased]`.
- **`README.md`** — розділи, яких стосується зміна (включно з mermaid-діаграмою
  логіки, якщо змінився сам packet-flow правил).

Це не опціонально. Зміна коду без оновлення документації в тому самому коміті
не приймається.

## Домен та стиль коду

- Не додавати зайвих абстракцій і обробників помилок без потреби — скрипти
  прості й мають лишатись такими.
- Не дублювати логіку: генератори nft-фрагментів (`gen_level_rules`,
  `gen_srv_rules` тощо) мають лишатись єдиним джерелом для IPv4/IPv6 та
  input/forward варіантів — не копіювати блоки правил вручну.
- Коментарі — українською. Не писати коментар, якщо `WHY` очевидний з коду.
- Списки `trusted`/`ignore`/`permanentBlock` редагуються через
  `scan-detect-tool` або override-файли в `/etc/nft-scandetect/` — не
  хардкодити конкретні IP/мережі всередині скриптів.
- Зміни в `nft-scan-detector` обов'язково проганяти через `nft -c -f` (dry-run
  перевірка синтаксису) перед `nft -f` — атомарність застосування не порушувати.
- Не запускати періодичний виклик `nft-scan-detector` (cron/timer) без
  урахування того, що він скидає live-стан `scan`/`level*`/`srv_*` (див.
  README → "Відомі обмеження і TODO") — це свідоме, поки не переглянуте рішення.
